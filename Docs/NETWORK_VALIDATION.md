# TCP 联机与通关退出验证

2026-11-02，Unity 6000.3.27f2。

## 已确认的连接故障

- 穿透原目标为 `127.0.0.1:7799`，公网为 `frp-six.com:24456`。
- 本机 `netsh interface ipv4/ipv6 show excludedportrange protocol=tcp` 均列出 `7729–7828`；7799 位于保留范围内。
- Unity Telepathy 与独立 TcpListener 绑定 7799 都得到访问拒绝。Telepathy 在后台线程绑定失败，Mirror 本地 Host 仍可能报告房间创建成功。
- 18099 实际绑定成功。用户已将穿透本地目标改为 `127.0.0.1:18099`。

## 修改

- 创建房间前预先绑定端口，明确区分系统禁止与端口占用；运行中监测监听线程退出。
- 客户端保留 Telepathy 的 socket 失败原因及 Mirror 传输错误；收到房间成员消息后才显示已加入，握手受超时约束。
- 房主创建成功提示保留实际 TCP 本地端口。
- 通关菜单增加“退出游戏”，保留单人“再来一次”和现有联机“返回主界面”，接入上下导航。

## 验证证据

- 7799 创建失败时不启动 Mirror Server、不进入 Busy 状态，并明确提示系统保留或禁止。
- 18099 Host 与独立 Telepathy 客户端经本地 TCP 完成 Ready / TrialHello / TrialLobby 交换，双方成员包含 HostProbe、TunnelProbe。
- 同一测试客户端经真实公网 `frp-six.com:24456` 完成以上交换，双方成员名字一致。证据：`Logs/Trial/PublicTunnelValidation.txt`。
- 连接本地无监听端口时保留 SocketException 的“积极拒绝”原因；传输错误不被断开回调覆盖；主动离开提示正确。
- 占用端口创建房间被拒绝；连接只接受 TCP、没有房间协议的监听器时保持“正在加入”，到达握手截止时间后正确断开并提示握手超时。
- 在 Play Mode 击杀 Boss 后，菜单显示“再来一次”和“退出游戏”；检查两个按钮的上下导航；实际调用重开按钮后回到 Playing，再次通关并调用退出按钮后结束 Play Mode。
- 通关界面截图：`Logs/Trial/Victory-Exit.png`。
- 最终 Unity 重新编译通过，编译错误与警告均为 0；验证结束后退出 Play Mode。

## 复测与边界

房主游戏端口填 `18099`，穿透本地目标填 `127.0.0.1:18099`；同伴填 `frp-six.com`、端口 `24456`。

公网验证使用同一机器上的独立 TCP 客户端经过公网中继，覆盖房间握手和名字交换；未验证另一台电脑上的完整游戏进程与持续战斗同步。测试客户端没有持续发送游戏心跳，不能用于长时间连接稳定性结论。

本次没有重新构建发行包。使用新错误提示及通关按钮需要重新构建；修正穿透本地端口本身也适用于原游戏包。
